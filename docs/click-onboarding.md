# 点击接入智能体

打开 Workdesk 菜单中的「设置与接入」。

1. 查看本机识别结果：Hermes 可执行文件与网关状态分别显示。需要时点击「重新识别」。检查使用公开的 `hermes gateway status`，不会启动服务或修改 Hermes 配置。
2. 选择已有身份（通常是 `local-agent`）和项目。首次使用可点击「创建本机身份 local-agent」，私钥由程序保存在 `~/.workdesk-credentials/local-agent.key`，不会显示内容。已有身份不会被重建或换钥。
3. 点击「授权所选身份接入当前项目」。这只授予所选项目的上报权限，不授予创建项目权限；检测或登记身份都不会自行授权。
4. 点击「检查连接并写入测试动态」。只有收到该事件的 `accepted` 签名协议回执才显示成功。项目会出现一条明确标注的连接检查动态，不修改任何任务状态。

已有绑定在向导下方显示，可点击「撤销」。原命令与手动映射保留在折叠的「高级」区域。已有凭据不在默认位置时，界面会显示此限制；不会猜测或搬动密钥。

## 状态含义

- 发现 Hermes 目录不代表已找到可执行文件；找到可执行文件不代表网关运行。
- 网关状态仅是按需检查时的结果；不进行常驻轮询。
- 项目绑定不代表签名写入成功；测试成功也不代表 QQ 消息已经收发。
- 向导不读取聊天、不发送 QQ 消息，也不把历史 accepted 动态当作在线证明。
- 目前自动发现支持 Hermes 的 PATH、`~/.local/bin`、Homebrew 与 `/usr/local/bin` 安装位置。其他智能体可以通过现有签名 CLI 协议主动上报，尚未提供自动发现。
- 这不是自动同步所有对话的功能。接入后的智能体仍须主动上报；现有 Hermes Workdesk 上报技能可以继续复用原身份与绑定。

## 验证与隔离

`swift run CoreChecks` 覆盖空环境、默认路径发现、身份复用、无隐式授权、accepted 回执、撤销、项目隔离和别名冲突。真实检查签名、收件箱、存储和回执全链路均在隔离 fixture 中执行。

指定 `WORKDESK_DATA_DIR` 时，点击创建身份使用该隔离目录下的 `credentials`，不会触碰真实用户凭据。`scripts/check-launch.py` 对打包应用验证启动、迁移、目录事件和 CLI 回执。
